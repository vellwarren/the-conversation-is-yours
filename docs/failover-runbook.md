# 故障切换演练

## 原则

- 只在 turn 边界切换；
- 已流出正文的失败轮不静默重试到另一个 provider；
- 写工具调用必须有幂等键；
- 付费 API 切换必须显式；
- 故障时保留权威历史，派生 session 可以丢弃。

## 演练 A：Claude Code 认证失败

1. 使用测试配置提供无效凭证；
2. 发起一个显式 CC turn；
3. 确认返回规范化错误，且没有调用 API；
4. 确认失败轮没有保存伪造的 assistant 消息；
5. 人工选择 API；
6. 确认 API 从最后一个成功 turn 继续。

## 演练 B：resume session 损坏

1. 在测试存储中放入无效 session id；
2. 确认 adapter 作废它；
3. 仅在尚未流出正文时，允许从权威历史 fresh rebuild；
4. 确认没有重复保存用户消息或执行写工具。

## 演练 C：API 429/5xx

1. 使用可控 fake endpoint 返回错误；
2. 确认系统不会自动切回 CC；
3. 由用户或运维明确选择下一条线路；
4. 记录选择与预算责任，不记录消息正文。

## 演练 D：跨线路长会话

1. 构造超过 API 安全水位的合成历史；
2. 从 CC 切到 API；
3. 确认应用先执行可审计的摘要/压缩；
4. 检查关键事实是否保留；
5. 记录冷缓存首轮成本与延迟。

## 验收表

| 检查项 | 必须满足 |
| --- | --- |
| 权威历史 | 最后一个成功 turn 完整存在 |
| 半截输出 | 不与备用 provider 输出拼接 |
| 写副作用 | 不重复执行 |
| 计费 | 没有未经批准的 API 请求 |
| session | 过期/损坏映射已作废 |
| 日志 | 无正文、token、密钥和完整 session id |
| 恢复 | 下一条线路能从权威历史继续 |
